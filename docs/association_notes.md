# 接口路链与海南 OSM 网页数据关联

按用户要求先对照整条高速主线，再逐个互通与匝道收费单元匹配。仅生成派生关联属性，不修改 API 原始响应、OSM 编号或原始道路几何。网页现已采用项目路链编号，映射表中 `linkId` 为项目编号，`osmLinkId` 仅保留来源标识，详见 [路链编号规则](link_numbering.md)。

## 数据与坐标

接口版本为 `V20260824114228`：279 条路链、275 条连通关系、58 个收费单元、50 座门架。现有地图为 10,680 条 OSM 拆分路链。业务路链编号与 OSM 编号没有直接交集；全部业务编号以 G9811 开头，空间范围为海口至屯昌一带，不能将其用于确认其他高速的方向。

以明确单向通行的 OSM 道路作距离对照，558 个业务端点与道路的距离中位数为：直接按 WGS84 约 458 米，按 GCJ-02 与 OSM 转换后的坐标比较约 3.2 米。`association_report.json` 中的 `coordinateAssessment` 保留了两种假设的统计。协议只明确门架为 GCJ-02，业务路链和收费单元采用 GCJ-02 仍是空间证据支持的假设，待提供方确认。

## 主线：先对照整条 G9811

从 OSM 的 G9811 主线建立完整有向链，先区分两幅车道及 OSM 中断开的片段。与业务主线端点、当前路链的接口方向进行整体对照，其中一幅有 70 个一致的 DOWN 投票，另一幅有 68 个一致的 UP 投票；无投票的片段保留未知。这里的链上累积距离用于相对位置比较，不是业务桩号。

业务数据按 17 个主线收费单元组织，共 150 条主线路链。140 条可沿主线对齐端点和顺序，133 条可检查的主线接口连接顺序均一致。端点和顺序对齐只是候选：仍需通过长度、门架及歧义检查才写入网页关联。没有将接口方向扩展到整条高速或未覆盖的区域。

## 匝道：逐个收费单元核对

另外 41 个匝道或服务区收费单元分别建立局部匹配范围。匝道要求路径属于 `motorway_link`，仅在该单元业务坐标包络及 150 米缓冲内找有向道路路径，避免误连到另一互通。业务上下行与收费单元名称不一致时保留冲突，不覆盖地图方向。4 条服务区内部道路暂不强行归类匹配。

OSM 互通名称缺失较多，名称用于组织业务单元，并不作为同名即对应的证据。复杂匝道、共用道路和道路等级差异仍需人工复核。

## 逐条检查条件

- 起点和终点距候选道路均不超过 20 米。
- 沿 OSM 单向通行方向有完整连续路径；主线候选需属于整条高速对照得到的对应车道。
- 路径长度与接口长度相差不超过 `max(30 米, 15%)`；保留误差值供复核。
- 同路链门架需在候选路径范围内且距道路不超过 20 米。
- 存在形状不同且评分接近的替代路径时，保留歧义，不写入关联。
- 一个业务路链可对应多段 OSM，道路的一部分也可对应多个业务路链，以有向几何比例保存覆盖区间。
- 只读取 `BDS_LINKREL_LIST` 中 `currentLinkId` 的方向，不把关系方向复制给 `nextLinkId`。
- OSM 段覆盖率达到 80%、所有关联方向一致、没有名称或顺序冲突时，才显示“上行/下行（接口空间关联）”；其余保留原有推断或待确认。

## 网页与输出

地图保留完整路网，将已关联路链用蓝色标注；可按业务路链 ID、单元 ID、名称和桩号查找；详情展示关联编号、收费单元、接口方向、门架和业务连通关系。概览中展开“按高速与收费单元逐一对照”，可查看整条 G9811 主线，并逐个定位收费单元。定位操作只移动视野，其他路段仍正常显示。

`outputs/associations/` 内：

- `highway_unit_comparison.csv`：按主线/匝道收费单元逐项统计，通过、歧义与未匹配数量。
- `main_corridor_candidates.csv`：140 条主线整体对齐候选及逐条检查状态，用于复核长度不符等问题。
- `business_osm_mapping.csv` / `.json`：完整业务编号—OSM 编号对照、覆盖区间及失败原因。
- `association_report.json`：坐标假设、主线完整链、方向投票、连接顺序检查和覆盖报告。

关联与方向属性仅生成到 `hainan-web/public/data/hainan.json`，接口几何不会替换真实 OSM 道路形状。

## 重新生成与验证

在项目根目录运行：

```bash
npm --prefix hainan-web run data
python3 -m unittest discover -s tests -v
npm --prefix hainan-web run build
```

数据生成脚本读取 `outputs/gis_data/latest.json` 指向的本地接口快照，无需联网。Python 匹配器使用标准库，不依赖额外 GIS 软件。

## OSM 道路连接更新

道路侧已从同源 PBF 共享节点补齐跨原链有向关系，并在内部共享节点处补切。匹配网络也使用确认后的节点连接，避免仅凭相同坐标连接不同 OSM 节点。GIS 关联检查阈值保持原规则，当前匹配仍为 124 条；详情相邻路链采用完整 OSM 拓扑。见 [OSM 跨原链拓扑说明](osm_topology.md)。
