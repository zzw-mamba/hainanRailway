# 海南路链编号规则

网页、派生关联对照表与拆分内部连通关系使用项目编号。OSM 原始数据和接口业务编号分别保留，均不直接充当网页路链编号。

## 路链编号

格式：`HN-路线代码-道路类型-六位序号`。

例如 `HN-G9811-M-001345`：

| 部分 | 规律 |
|---|---|
| `HN` | 海南项目固定前缀 |
| `G9811` | 首次分配时源数据的路线编号 |
| `M` | 高速主线；`R` 为高速匝道，`O` 为其他道路类型 |
| `001345` | 该路线和类型下的唯一序号，从 `000001` 开始，六位补零 |

路线编号缺失时用 `UN`，例如 `HN-UN-R-000001`。共线路线按字母数字排序、去重后用 `+` 连接，例如 `HN-G15+G75-M-000001`。匝道原始数据没有路线标签时使用 `UN`，不会为了补全编号而猜测所属高速。

上下行、关联状态、桩号、长度均不进入编号。因此方向或业务关联修正不会改变现有编号。序号是项目内部标识，不是公里桩号，也不表示行驶顺序、上下行奇偶数或运营商业务编码。

## 原链编号

拆分前的原链使用 `HN-SRC-六位序号`，例如 `HN-SRC-000630`。同一原链拆出的路段共享该原链编号；路段的 `segment_index` 继续表示原来的拆分段顺序。原链编号和路段编号属于两个独立编号范围。

## 分配与稳定性

首次分配时，在每个路线/类型分组内按道路几何的最南纬度、最西经度排序；相同位置时用原始记录标识打破平局。原链也按几何位置分配。

分配结果保存在 `outputs/identifiers/link_id_registry.json`。此后相同源记录复用已分配编号；新记录从相应组的下一个序号追加。输入文件顺序改变、新道路插入到更南位置或旧道路退出，不会重新排列已有编号。已使用编号保留，不重复分配。

编号中的路线/类型反映首次分配时的分类；后续分类变化也保留已分配编号。若重新拆分或上游记录标识变化，产生新的源记录，则分配新编号并保留旧记录映射。六位序号达到 `999999` 后停止分配并报错，避免重复。

**注册表应和数据一起保存、备份，不应作为临时输出删除。** 在注册表丢失且源数据发生变化后重建，不能保证原编号延续。

## 数据字段与追溯

- `properties.link_id`：项目路链编号，列表、地图、复制、搜索和前后段跳转均使用该字段。
- `properties.source_link_id`：项目原链编号。
- `properties.osm_link_id`：原 OSM 派生路段标识，仅作来源追溯和兼容搜索。
- `properties.osm_source_link_id`：原 OSM 原链标识。
- 原 `properties.id`、OSM 标签和几何坐标保持原值。
- 接口业务编号保持提供方原值，显示为接口数据关联中的编号；不能用它替代项目编号，因为两者是多对多关系。

`outputs/identifiers/link_id_mapping.csv` / `.json` 提供项目编号、原链编号、旧 OSM 标识和 Way ID 的完整对照，共 10,680 条路段。

`outputs/associations/business_osm_mapping.csv` 新增 `linkId`（项目编号），并保留 `osmLinkId`（源标识）。所有网页拆分内部关系的 `currentLinkId`、`nextLinkId` 和 `source_link_id` 同步迁移到项目编号。

## 高亮与完整路网

普通主线为绿色、匝道为橙色、关联路段为蓝色。点击选中的任何路段，包括关联路段，均以更粗的黄色线显示；取消选择后恢复其对应颜色。定位业务路链或收费单元时仍保留完整路网。

在项目根目录重新生成：

```bash
npm --prefix hainan-web run data
```

## 调整长度后的编号

页面重新切分会比较源路链及几何边界。源路链和边界不变时复用已有编号；即使拆分序号相同，边界变化也会分配新编号，避免一个编号代表不同路段。曾使用过的几何边界再次生成时复用对应编号。原链 `HN-SRC` 编号保持一致；几何指纹由编号注册表保存，网页仍使用原来的编号格式。
